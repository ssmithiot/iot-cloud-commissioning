# GW006 USB-485 BACnet router pilot

This is the staging pilot contract for GW006. It leaves the separate Switch
(`janus.service`) unchanged while giving the USB-485 MS/TP trunk one dedicated
router/data-plane service. GW015 and production are out of scope.

The USB router is a reversible routing-authority layer, not a destructive
replacement for standard BASRT-B/BAC-RTR routing. The complete enable/disable
state and UI contract is in
[`gw006-edge-router-authority-model.md`](gw006-edge-router-authority-model.md).

## Port and ownership contract

| Owner | Resource | Pilot value | Rule |
| --- | --- | --- | --- |
| Switch application | BACnet/IP socket | UDP 47808 | Unchanged; the edge agent must not bind it. |
| `iot-cx-mstp-router.service` | BACnet/IP router endpoint | UDP 47809 | Sole router/BBMD endpoint for the USB-485 pilot. |
| `iot-cx-mstp-router.service` | Serial MS/TP medium | `/dev/serial/by-id/usb-UTEK_USB__-__Serial_Cable_FT8NOQWB-if00-port0` | Sole owner of the adapter and token state. |
| `iot-cx-mstp-router.service` | MS/TP network number | 202 | Dedicated, nonzero BACnet network number. |
| `iot-cx-agent` | BACnet/IP client source | UDP 47814 | Registers as a Foreign Device with `192.168.1.200:47809`; never opens the serial device. |

Two processes must never share the same local IP/UDP socket. In particular,
`SO_REUSEADDR` is not a BACnet traffic-sharing or routing mechanism.

## How the agent reaches the router

The agent's BACnet command-line tools use the upstream BACnet stack's Foreign
Device Registration configuration. The agent binds its own source port
(`BACNET_IP_PORT=47814`) and registers with the router's BBMD endpoint
(`BACNET_BBMD_ADDRESS=192.168.1.200`, `BACNET_BBMD_PORT=47809`). The router
keeps the Foreign Device Table and returns replies to the source IP/UDP port
that registered. This is BACnet routing, not UDP port forwarding.

The router must accept FDR on its own BACnet/IP port. The upstream
`router-mstp` implementation includes BBMD handling; that capability must be
proven on the exact GW006 binary before deployment. Read-only inspection on
2026-07-22 verified that GW006 runs BACnet Stack `1.6.0-rc1` and that its
`router-mstp` binary contains the Foreign Device Registration, foreign-device
table, and FDT-forwarding handlers. The currently active service remains on
UDP 47808 and MS/TP network 2; this task did not change it.

## Intended saved router configuration

The router helper is deliberately guarded: it refuses to replace an unmanaged
unit until its existing unit has been backed up and an explicit migration is
performed. The saved configuration must resolve to:

```json
{
  "enabled": true,
  "interface": "enp1s0",
  "ip_port": 47809,
  "bbmd_port": 47809,
  "ip_network": 1,
  "serial_device": "/dev/serial/by-id/usb-UTEK_USB__-__Serial_Cable_FT8NOQWB-if00-port0",
  "baud": 38400,
  "mstp_mac": 2,
  "mstp_network": 202,
  "max_master": 127,
  "max_info_frames": 128
}
```

The pilot agent configuration is:

```yaml
bacnet_default_port: 47814
bacnet:
  router_profile: custom
  default_port: 47814
  bbmd_address: 192.168.1.200
  bbmd_port: 47809
```

## Required live validation after an approved deployment

Capture UDP traffic on the gateway and preserve the output with the pilot
record. Verify each item independently:

1. Switch discovery, read, and write continue through UDP 47808.
2. Edge-agent discovery, read, and write originate at UDP 47814, register to
   the router at UDP 47809, and route to MS/TP network 202.
3. Run switch and edge-agent workloads simultaneously; there must be no
   duplicate Who-Is storms or cross-delivered replies.
4. Confirm only the router process has `/dev/ttyUSB0` open, MS/TP token
   passing remains stable, and the agent uses no serial device.
5. Restart the router cleanly, confirm only its lock/serial ownership returns,
   and rerun the preceding checks.
6. Confirm the edge agent is the sole concurrent UDP 47814 BACnet client and
   that no unrelated service has been displaced. On the pre-deployment GW006
   baseline, `edge-bacnet-ui.service` also launches transient BACnet clients
   from 47814 without using the agent's lock. Do not run its BACnet operations
   concurrently with the agent until it is moved to another approved source
   port or both clients share a single lock/coordination mechanism.

The live work requires an approved maintenance window, a root-capable staging
operator, and a rollback plan.

## 2026-07-23 staging result

The first GW006 staging cutover was rolled back automatically and its original
files were checksum-verified afterward. The router cutover itself succeeded:
the exact gateway binary started on UDP 47809, announced MS/TP network 202,
and used the stable USB-by-id device. The agent then failed its startup health
check because the gateway checkout is a detached, older revision
(`d899d80a0f217eac6ff62aa55f48a771bd129558`) whose `AgentConfig` has additional
required trend and inventory fields. The canonical Linux workspace was
`main` at `dbb74c308a17bcb4e54312189a3e500ca23a1fe2`; copying only the pilot
modules replaced the older configuration API and caused an immediate restart
loop. Rollback restored the original router (UDP 47808, MS/TP network 2),
agent, and UI, and verified every backed-up checksum.

Do not retry the router cutover by copying individual agent modules. First
reconcile the complete GW006 agent runtime to a tested revision of this
repository (or port the FDR change onto its exact deployed revision), then
repeat the staged validation from the saved backup and rollback package.

## 2026-07-23 compatible release deployment

GW006's deployed `edge-agent-v0.1.9` was confirmed to descend from
`edge-agent-v0.1.8`. A narrow compatibility patch was built against that
deployed release, preserving its release-specific trend and inventory
configuration fields while adding only the FDR settings and command
environment. The router then ran on UDP 47809, announced MS/TP network 202,
and exclusively used the stable USB-by-id serial adapter.

Live staging validation passed: an agent-compatible client bound UDP 47814,
registered in the router FDT as `192.168.1.200:47814`, discovered device 1 on
network 202, read AV1/PV, wrote the existing value at priority 1, and
relinquished priority 1 successfully. Router restart and complete gateway
reboot persistence were also verified, including a post-reboot FDR discovery,
read, and UI recovery. The Edge UI navigation-only patch record is in
`docs/staging-patches/gw006-edge-ui/` and the exact gateway before/after files
and rollback scripts remain under `/home/swadmin/gw006-usb485-staging/`.

The remaining operational limitation is intentional: the Edge UI has transient
BACnet clients on UDP 47814, so it was stopped during exclusive agent FDR
tests. Do not run Edge UI BACnet actions and agent BACnet jobs concurrently
until both use a shared lock or separate source ports.
