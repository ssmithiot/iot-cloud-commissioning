#### The 5 baseline failures

Four were pre-existing test-order dependencies, all passing in isolation and
failing in a full run:

- `edge-agent/tests/test_trends.py::test_sampling_logs_safe_route_diagnostics`
- `edge-agent/tests/test_trends.py::test_local_sampler_not_invoked_when_flag_is_absent`
- `edge-agent/tests/test_tunnel.py::test_handle_tunnel_message_proxies_to_local_ui`
- `edge-agent/tests/test_tunnel.py::test_handle_tunnel_message_logs_redirect_shape_without_location_value`

All four are fixed, by fixing the two underlying defects rather than the tests:

1. `cloud-api/alembic/env.py` called `fileConfig()` with the default
   `disable_existing_loggers=True`. Any in-process migration — the release
   gate, and `test_uuid_schema_alignment` / `test_legacy_schema_reconciliation`
   — silently switched off application logging for everything that ran
   afterwards. Verified by bisection: those two files, and only those two,
   reproduced the failure.
2. `iot_cx_agent/main.py` held a module-level "already logged" latch that
   leaked between tests. It was removed as part of the trend-step refactor.

#### The 1 remaining failure

`cloud-api/tests/test_api.py::test_gateway_workspace_contains_discovery_progress_ui`

Fails on `assert "Remove device" in response.text`. This is **pre-existing and
not introduced by 0.2.0**. Evidence:

   which side is correct.

   post-baseline maintenance commits whose cloud-side approval is recorded as
   undecided. The agent payload is unaffected, but the cloud-side changes now
   ride into 0.2.0 and should be approved explicitly.

4. **`sample_configured_trends`** (the older cloud-configured trend path) still
   polls the cloud for configuration every cycle and coexists with the
   Edge-owned path. Whether it should be retired now that the Edge is
   authoritative is an open design question.
5. The Edge UI has **no automated coverage of the graph's client-side
   JavaScript**; graph tests assert the serialised series data only.
